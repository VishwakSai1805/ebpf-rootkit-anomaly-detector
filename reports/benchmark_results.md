# Benchmark results

Generated by `python -m benchmarks.run_benchmark` (deterministic; seeds fixed).

> **Read this first.** Traffic is *synthetic* (see `collector/scenarios.py`): benign workloads include hard negatives (sudo/su, gdb/strace, `LD_PRELOAD` dev tools, sshd privilege drops, shell pipelines) but the attack chains are idealised. These numbers measure separability on this generator, not production false-positive rates on a real fleet.

## Setup

- Training: 500 benign sessions only (unsupervised); thresholds = p99.7 of held-out benign scores (IF 0.6394, AE 0.0871).
- Test: 3 independent corpora (seeds [777, 778, 779]), each 400 benign + 100 sessions x 5 attack classes. Pooled: 1200 benign / 1500 attack sessions.
- *Session detected* = a window containing an attack event is flagged. *Session false positive* = any window of a benign session flagged (a strict criterion: sessions have dozens of windows).
- Environment: Python 3.13.18, numpy 2.5.3, scikit-learn 1.9.1, x86_64; total benchmark runtime 29s.

## Observations / limitations

- On this synthetic data the Isolation Forest alone has low recall (attacks live in a handful of sparse behavioural columns) and the autoencoder does nearly all the work; compare the `fused` and `autoencoder` rows: OR-fusing the forest adds its false positives while adding no session-level recall beyond the autoencoder. It is kept as an independent second opinion for ptrace-heavy windows and for real data whose structure may differ - tune or drop it for your environment.
- Residual false positives come from the intentionally hard benign classes (gdb/strace sessions, `LD_PRELOAD` dev tooling). `ld_preload` recall is the lowest because one attack variant (a single `LD_PRELOAD` exec, no `ld.so.preload` write) is behaviourally identical to the benign dev-tool case.
- Hidden-PID detection requires a trustworthy `/proc` snapshot and a grace period (1 s) to absorb fork/exit races.
- Real kernels produce much higher event volume and noisier context than this generator; re-calibrate thresholds on your own benign baseline (`python -m ml.train`) before relying on alerts.
